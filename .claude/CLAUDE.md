# 릴스 대본 기획 도구 — 이 폴더에서 Claude Code가 지킬 것

## 처음 온 사람

사용자가 "구축 가이드대로 진행해줘", "세팅해줘", "처음이에요", "이어서 해줘"라고 하면 `SETUP.md`를 열고 그 문서의 원칙과 단계를 그대로 따른다. 한 단계씩, 확인 후 다음으로.

## 명령 (사용자가 말로 시키면 이걸 실행)

- "대본 써줘" / "R-012로 기획해줘" / "이번 공구 대본" → `/릴스대본기획` 스킬
- "계정 세팅" / "내 계정 문서 만들어줘" → `/계정세팅` (v0.2). 그전에는 SETUP.md 3단계대로 직접
- "이건 하지 마" / "이 훅 추가해" / "이 말투 쓰자" / "대표대본 갱신" → SKILL.md 성장 동작. 계정 폴더의 문서만 고친다
- "템플릿 업데이트 받아줘" → 원본 저장소의 최신 ZIP을 받아 `.claude/` 폴더만 통째로 교체한다. `계정/`·`기획/`·`.env`·`.setup-progress.json`은 절대 건드리지 않는다. 교체 전에 현재 `.claude/`를 `.claude.bak/`으로 옮겨 두고, 끝나면 "무엇이 바뀌었는지" 한 줄 보고
- "되돌려줘" → 직전에 고친 파일을 원래대로. git이 있으면 `git checkout -- <파일>`, 없으면 Claude가 고치기 전에 만들어 둔 `.bak` 사본으로

## 파일 주인 — 둘로 나뉜다

- `.claude/` 는 도구(템플릿) 것. 업데이트 때 통째로 바뀐다. 여기 있는 문서를 사용자 맞춤으로 고치지 않는다 — 고치고 싶은 것이 있으면 계정 폴더로 옮겨 적는다
- `계정/<핸들>/`·`기획/`·`.env`·`.setup-progress.json` 은 사용자 것. 템플릿 업데이트가 덮어쓰지 않는다
- `계정/_template/` 은 빈 양식. 복제해서 쓰고, 양식 자체는 고치지 않는다

## 기능 요청이 오면 — 이 순서로 분류하고 답한다

| 요청이 이런 거면 | 하는 것 |
|---|---|
| 출력 모양·말투·질문 문구 바꾸기 | 계정 폴더 문서(DNA·안티패턴)에 반영. `.claude/` 안 문서는 고치지 않는다 |
| 새 점검 항목·새 형식·새 훅 | 계정 폴더의 형식.md·훅.md에 SKILL.md "추가 방법" 규칙대로. 근거 인용 없이는 추가하지 않는다 |
| 데이터 소스 바꾸기(다른 대시보드·다른 파일) | `.env`만 고친다. fetch.sh를 고치지 않는다 |
| 웹 화면·자동 발송·여러 사람 동시 사용 | 이 도구의 범위 밖. "이건 이 도구가 하는 일이 아니에요"라고 말하고, 대시보드 쪽 기능인지 안내 |

## 하지 않는 것

- `.env` 값을 채팅에 출력하거나 다른 파일에 복사하지 않는다
- 사용자가 직접 쓴 문장(초안·대사)을 고치지 않는다
- 사용자를 부르는 호칭을 쓰지 않는다. 존댓말
